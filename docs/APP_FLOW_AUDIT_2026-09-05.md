## 1. 판정

**뒤로가기 플로우 개선이 필요합니다.** 가장 큰 문제는 브라우저 이동 이력 부재, 설문 상태 유실, 진입 경로와 다른 복귀 목적지입니다. 타입 검사·빌드가 통과해도 사용자 이동 흐름은 여러 곳에서 깨집니다.

요청한 전체 화면과 이동 핸들러를 코드로 검토하고, 비회원 화면 및 접근 가능한 보조 화면을 브라우저로 검증했습니다. **회원 정상 흐름·실결제·실기기까지 전체 통과한 보고서는 아닙니다.** 확인하지 못한 항목은 아래에 명시했습니다.

우선 확인할 문제:

1. 설문 5번 → 로그인 → 뒤로: **답변과 진행 위치가 사라지고 1번으로 복귀**합니다.
2. 미응답 문항에서는 **이전 버튼 자체가 없습니다**. 응답해야 이전으로 갈 수 있습니다.
3. 이전 문항으로 돌아오면 **다음 버튼까지 사라져 기존 답변을 다시 눌러야** 합니다.
4. 브라우저 뒤로가기는 이전 앱 화면이 아닌 **앱 밖으로 이동**합니다.
5. 랜딩 → 로그인 → 뒤로가 **랜딩 대신 동의 화면**으로 연결됩니다.
6. 재측정 취소가 원래 결과 화면이 아닌 랜딩으로 연결됩니다.

## 2. 검증 조건과 증거 해석

- 기준 커밋: `6880d76e4590184f5306ec2954903bfed5f6c454` + 현재 미커밋 변경. 기존 문서와 달리 장바구니, 멤버십·결제의 공통 탭 셸도 포함했습니다.
- 실행: Codex 내장 브라우저, 주 검증 390×844 CSS px, 추가 로그인·가입 화면 360×640. 실제 Android Chrome/Safari 및 소프트 키보드 검증은 아닙니다.
- 실행 주소: `http://127.0.0.1:3107`. Vite로 현재 소스를 실행했습니다. Supabase와 결제 API는 응답하지 않는 로컬 `127.0.0.1:3199`로 지정해 운영 쓰기를 방지했습니다. 실제 계정 로그인·회원 생성·주문·결제·운영 DB 수정은 하지 않았습니다.
- `?ui=membership/checkout/cart/journeyIntro/journeyToday/auth`는 앱에 이미 존재하는 미리보기입니다. **이 미리보기는 App의 인증 bootstrap을 생략**하므로 정상 회원 진입 검증과 구분해야 합니다.
- 설문·안내·리포트·다음 저니·빈 미션은 임시 Vite 플러그인이 메모리에서 미리보기 허용 목록만 확장하여 직접 진입했습니다. 소스 파일·화면 전환 콜백은 수정하지 않았습니다. 약관 동의 수락과 서버 인증을 대신 실행하지 않았습니다.
- 따라서 동의 제출 → 안내의 완전한 통합 실행은 미검증이고, 안내 이후 32문항은 직접 진입 후 실제 버튼을 순서대로 조작했습니다. 자동 채우기 버튼으로 완주한 것이 아닙니다.
- 결과 생성 후 `ui`를 제거한 일반 결과 URL에서도 복원·새로고침·탭·로그인 취소·재측정을 확인했습니다.
- 증거 등급: **실행** = 브라우저에서 관찰 / **QA 실행** = 미리보기·경계 상태에서 관찰, 정상 진입은 미확인 / **코드 확인** = 구현상 원인 확인, 회원·실서버 재현은 미완료.
- 코드 해시 비교에서 `src`와 `package-lock.json`은 검증 기준선과 동일했습니다. 검증 중 `package.json`에 외부 변경(`verify:fulfillment` 추가)이 관찰되었습니다. 해당 새 검사는 실행하지 않았습니다.

## 3. 실행으로 확인한 문제

### F01 · 높음 · 브라우저 뒤로가기가 앱 내부 경로를 복원하지 않음

- 경로: 신규 탭 → 랜딩 → 분석 시작 → 동의 → 브라우저 뒤로 → 앞으로.
- 기대: 동의에서 랜딩으로 복귀하고 앞으로가기로 동의를 복원.
- 실제: 뒤로는 `about:blank`로 앱을 벗어났고 앞으로는 랜딩으로 재시작했습니다.
- 영향: 화면 버튼과 브라우저/휴대폰 뒤로가기의 의미가 달라지고 중간 작업을 잃을 수 있습니다.
- 원인: `App.tsx`는 `currentScreen` 상태만 변경하며 결과 ID에 대해서만 `history.replaceState`를 호출합니다. `pushState/popstate` 연결이 없습니다.
- 제안: 화면·모달 이동과 브라우저 이력을 연결하고, 직접 진입·완료 후 복귀를 별도 정의합니다. 탭 이동을 모두 이력에 넣을지는 UX 결정이 필요합니다.

### F02 · 높음 · 미응답 문항에 이전/나가기 버튼이 없음

- 경로: 설문 1번 응답 → 다음 → 2번 미응답 상태.
- 기대: 답을 고르지 않고 이전 문항을 확인하거나 설문을 중단할 수 있어야 함.
- 실제: 로그인·임시 결과 버튼과 선택지만 있고 이전 버튼이 없습니다. 답을 고른 뒤에만 이전이 생깁니다. 첫 문항도 동일합니다.
- 영향: 뒤로가기 위해 임의의 답을 골라야 하고, 브라우저 뒤로는 F01 때문에 앱을 벗어납니다.
- 원인: `QuestionnaireScreen.tsx:284`의 `isGuidePhase` 조건 안에 `QuestionNavBar` 전체가 들어 있습니다.
- 제안: 이전/중단은 상시 제공하고 다음만 미응답 여부에 따라 제한합니다.

### F03 · 보통 · 이전 문항으로 돌아오면 다음 버튼이 사라짐

## 4. 코드에서 확인한 추가 문제 — 회원/실서버 재현 필요

### C01 · 높음 · 과거 측정 기록을 눌러도 선택한 결과 ID가 버려짐

`MeasurementSection`은 `onOpenResult(record.id)`를 호출하지만 `StatusScreen.tsx:209`는 ID를 받지 않는 래퍼로 연결합니다. App도 홈 탭만 선택합니다. 따라서 과거 기록을 골라도 기존 결과를 보여주는 연결입니다. 서로 다른 코드의 결과가 2건 이상인 테스트 계정으로 확인해야 합니다. 제안: 결과 ID를 App까지 전달하고 조회 대상·복귀 경로를 보존합니다.

### C02 · 보통 · 저니 오늘 화면 뒤로가기가 랜딩으로 고정

루틴 탭 또는 내 상태에서 저니 오늘로 들어갈 수 있지만 App의 JourneyToday onBack은 항상 landing입니다. 미리보기에서 실제 랜딩 이동은 확인했고, 회원 정상 진입 왕복은 미확인입니다. 제안: 진입 탭으로 복귀하거나 버튼을 ‘처음으로’로 명확히 구분합니다.

### C03 · 보통 · 저니 시작 중 멤버십 안내의 복귀 목적지가 다음 저니로 고정

`openJourneyIntro`의 자격 부족 분기와 `JourneyIntroScreen.onRequireSubscription`가 모두 `openMembership('journeyNext')`를 사용합니다. 루틴에서 시작했어도 멤버십 뒤로는 journeyNext가 됩니다. 제안: 실제 진입 화면을 저장하고 체험 소진·첫 시작·14일 완료 후 연장 경로를 각각 테스트합니다.

### C04 · 높음 · 미션 피드백 저장 실패에도 화면을 떠남

`JourneyMissionScreen.handleSubmitFeedback`은 `finally`에서 `onDone`을 호출합니다. 저장에 실패해도 오늘의 미션으로 빠져나가 입력을 다시 제출하기 어렵습니다. 실패 네트워크+회원 fixture에서 검증해야 합니다. 제안: 성공한 경우에만 이동하고 실패하면 선택값·재시도를 유지합니다.

### C05 · 보통 · 진행 중 타이머가 화면 이탈 시 재생성됨

공통 루틴의 `RoutineStepTimer`와 저니 미션의 남은 시간은 component state입니다. 탭 전환·접기·뒤로에 대한 중단 안내나 진행 중 타이머 복원이 없습니다. **공통 루틴 완료 체크는 localStorage에 저장하므로 완료 기록까지 모두 사라진다고 판단하지 않습니다.** 제안: 진행 중 타이머와 완료 기록 정책을 구분하고 일시정지/재개 또는 중단 확인을 제공합니다.

### C06 · 보통 · 분석 저장 요청이 오래 대기할 때 탈출 수단이 없음

App은 분석 화면에 onBack을 전달하지 않으며, 저장 완료를 기다린 다음 결과 화면으로 이동합니다. 즉시 실패는 로컬 결과로 정상 전환했지만 응답이 끝나지 않는 저장 요청에는 앱 수준 타임아웃/취소를 확인하지 못했습니다(문항 조회의 timeout과 구분). 제안: 로컬 결과를 먼저 제공하거나 저장 시간 제한·재시도·이탈 정책을 명시합니다. 무한 대기 실제 재현은 미실시입니다.

## 6. 남은 검증과 다음 수정 우선순위

### 아직 확인하지 못한 것

- 테스트 계정의 로그인 성공/세션 만료/로그아웃, 신규·기존 결과 연결, 유료/체험 소진 상태.
- 실제 콘텐츠가 있는 회원 루틴 타이머, 중단/재개, 피드백 X·저장, Day 7/14 리포트와 다음 저니.
- 장바구니 상품 담기·수량·삭제·주소 취소, 결제 완료·중복 결제/적립 방지. 운영 대신 격리된 테스트 DB와 결제 sandbox가 필요합니다.
- 모달 열린 상태의 브라우저 뒤로 및 연속 클릭. 현재 앱에서 액션 상세 full 모달은 도달 가능한 사용처가 없고, 피드백 시트는 회원 완료 상태가 필요합니다.
- 모든 버튼의 빠른 반복 클릭, 모든 화면의 새로고침·직접 진입 조합까지 실행한 것은 아닙니다.
- 실제 휴대폰 키보드, safe area, Safari 스와이프 뒤로, Android 브라우저 시스템 뒤로, 백그라운드 복귀.
