# MEBODY — 개발계 보안 하드닝

2026-08-29 점검에서 확인된 문제를 고칩니다. **개발계에 먼저 적용하고 검증한 뒤 운영계로 옮깁니다.**

`anon` 키는 브라우저 번들에 실려 나가는 공개 키입니다. 비밀이 아닙니다.

## 확인된 문제

| # | 문제 | 영향 |
|---|---|---|
| 1 | `body_code_content` RLS 꺼짐 + anon DELETE | 공개 키로 결과 콘텐츠 16행 삭제 → 전 사용자 결과 페이지 파손 |
| 2 | `admin_audit_logs` RLS 꺼짐 + anon 전체 권한 | 감사 로그 열람·위조·삭제 |
| 3 | `questionnaire_responses` `FOR ALL USING (true)` | 응답 380행 열람·수정·삭제 |
| 4 | public 전 테이블 anon INSERT/UPDATE/DELETE 권한 | 광범위한 쓰기 노출 |

## 실행 순서

| 파일 | 내용 | 앱 변경 |
|---|---|---|
| `200_dev_rls_fix.sql` | RLS 전면 활성화, 권한 회수 후 필요한 것만 재부여 | 불필요 |
| `210_response_read_lock.sql` | 응답 전체 열람 정책 제거, 회원 응답 보호, 조회 RPC 추가 | 이미 반영됨(RPC 우선 조회 + 폴백) |

## 검증

드라이런(롤백되는 트랜잭션)으로 **23건 통과**를 확인했습니다.

- 적용 전: anon이 콘텐츠 삭제 가능, 감사로그 열람 가능, 응답 380행 열람 가능
- 적용 후: 모두 `42501` 차단
- 기존 동작 유지: 문항 32 · 즉시액션 23 · 축매핑 8 · 16코드 · 상품 3 조회 정상
- **비회원 진단 저장·제출·조회 정상**
- 다른 회원의 응답은 보이지 않음 (실제 6행 → 보임 0행)

### 검증 중 발견한 것

`210` 초안에서 SELECT 정책을 전부 지웠더니 **비회원 진단 저장이 42501로 실패**했습니다.
앱이 `insert().select()` = `INSERT ... RETURNING` 을 쓰는데, RETURNING 은 반환 행을 읽을
SELECT 권한을 요구하기 때문입니다. 그대로 배포했으면 진단이 멈췄을 것이라 정책을 다시 설계했습니다.

## 남은 위험

비회원 응답(`user_id IS NULL`)은 여전히 열거 가능합니다. 답변과 계산 코드만 있고
이름·이메일·사용자 ID는 없지만 완전한 차단은 아닙니다.
막으려면 INSERT도 RPC로 바꿔야 하며, 진단 저장 경로 변경이라 별도 작업으로 둡니다.
